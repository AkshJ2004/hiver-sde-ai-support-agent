# Golden Set Labeling Guide

## Sampling Methodology

The golden evaluation set was built from 5,000 AppleSupport customer→brand
pairs extracted from the Customer Support on Twitter (TWCS) dataset.

**Stratified sampling** was used with these parameters:
- **Target size**: 200 examples (197 achieved)
- **Minimum per intent**: 15 (ensures rare classes like `account_or_security` are represented)
- **Remaining budget**: allocated proportionally to intent frequency
- **Diversity**: within each intent, examples were selected to span high/low classifier confidence and calm/frustrated tone
- **Random seed**: 42 (reproducible)

## Intent Distribution

| Intent | Count | % |
|---|---|---|
| general_inquiry | 65 | 33% |
| software_update_issue | 44 | 22% |
| app_or_performance | 26 | 13% |
| battery_or_power | 24 | 12% |
| connectivity | 20 | 10% |
| account_or_security | 18 | 9% |

## Labeling Criteria

### Intent labels

Each message is assigned exactly one intent:

- **software_update_issue**: The customer explicitly mentions an iOS/macOS/watchOS update, or the complaint is clearly triggered by a recent software change (e.g., "since the update", "after upgrading to iOS 11").
- **battery_or_power**: Battery drain, charging failure, overheating, device won't power on, unexpected shutdowns.
- **app_or_performance**: App crashes, device freezing, lag, slow performance, UI glitches. If the cause is explicitly an update, prefer `software_update_issue`.
- **connectivity**: WiFi, Bluetooth, cellular, signal issues, AirPods connection problems.
- **account_or_security**: Apple ID, password, locked account, 2FA, iCloud access, security concerns.
- **general_inquiry**: How-to questions, product info, general feedback, compliments, complaints that don't fit other categories.

### Edge cases

- **Multi-intent** (e.g., "update broke my wifi"): Choose the primary complaint. If the update is the cause, use `software_update_issue`. If the connectivity issue is the focus, use `connectivity`.
- **Vague frustration** (e.g., "fix your phone"): Use `general_inquiry` unless context strongly implies a specific issue.
- **Follow-up messages** without original context: Label based on what's explicitly stated.

### Decision labels

- **auto_handle**: The message can be safely addressed with a template or RAG-drafted reply. No identity verification, financial action, or nuanced judgment needed.
- **escalate**: The message requires human review because of:
  - Account/security sensitivity (always escalate `account_or_security`)
  - High frustration (profanity, threats, extreme dissatisfaction)
  - Low classifier confidence
  - Ambiguous or multi-faceted issue requiring judgment
  - Customer claims something actionable but provides no reference

## How to review

Each row in `golden_set.jsonl` has `"needs_review": true`. After verifying:
1. Correct the `intent` if the auto-label is wrong
2. Correct the `gold_decision` if the auto-decision is wrong
3. Set `"needs_review": false`
4. Optionally add notes explaining edge case decisions

The auto-labels are generated by the keyword heuristic classifier and should
be treated as a starting point, not ground truth.
